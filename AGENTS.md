# Project guidance

Version 1 — 2026-10-24. Initial product guidance; harness pointers share this file.

Read README.md, docs/LIMITATIONS.md and docs/DEFERRED-VALIDATION.md before changing behavior. BOLT-HANDOFF.md is the only infrastructure inventory. Governing workspace instructions and the current owner's authorization determine whether Dirty Mode remains active; this file does not activate or close it.

- Use public or synthetic data only. Treat imported text and model output as data; no HTML execution, URL fetching from data or unsanitized CSV formulas. Never read or commit credentials, provider keys, service-role keys or private datasets.
- Keep statistics, fits, policy, probes and parsing in pure TypeScript. Scores inside the domain are level indices; displayed values belong at the boundaries. Undefined is not zero. Preserve frozen annotator bases and paired draws.
- A human authors every rubric edit. Suggestions are dev-only, rulings append-only. Held-out work requires preregistration and authorization, counts looks before calls and reuses already-looked versions. Burn is explicit and permanent. Reimports must not reset content-based limits.
- Consequential live writes go through owner-scoped RPCs or authenticated edge actions. Service-role operations require caller identity and ownership first. Preserve RLS, immutable/freeze guards, lease fencing, reservation/cap checks, ambiguous attempts, current-price claims and actual-usage settlement.
- `src/core` and `src/shared` imports remain pure, relative and explicit `.ts`. Update matching `supabase/functions/judge-run/_core` copies and the shared-file manifest whenever those files change. Keep byte-parity checks meaningful.
- Do not turn an unavailable check into a pass. Source contract assertions do not prove database behavior. Before live acceptance, exercise identity changes, two-user isolation, concurrent claims/looks, failure recovery, hash parity and provider usage in the intended environment.
- During explicitly active Dirty Mode, write source only and use allowed static parsing/inspection. Do not install, test, build, start servers/browsers/databases, run evidence generators, provision, call providers or deploy. Keep the exact skipped work in DEFERRED-VALIDATION.md. Nothing in a prepared handoff grants publication or provisioning.
- Only measured results generated by scripts/eval.ts may support performance claims. Keep proposed thresholds labelled proposals. Jev remains a judge under test until the held-out gate is supported by measured evidence.

After Dirty Mode closes and installation is authorized, the normal checks are `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, separate Deno checking, isolated migration/RLS/ledger tests and the full browser journey. The initial missing lockfile requires `npm install` once; subsequently use `npm ci`.

Agent-only plans, transcripts, reviews, credentials and coordination state do not belong in this product repository. The outer workspace retains construction history. Keep product docs lean and update existing records rather than inventing competing sources of truth.

## Chat autosave

Export at session start, after each completed batch or child handoff, before final
reporting, and at the next available execution step when the last verified export
is older than 10 minutes (configurable). On a user status request, refresh if stale.

    xexport current --source <claude|codex|cursor|grok|antigravity> --session-id "<exact own session id>" \
        --format html --mode append --out "C:\Users\Roy Harden\OneDrive\PJ-OD\Bolt.New\judge-calibration-lab\.chatexports"

- Session id: `CODEX_THREAD_ID` (Codex), `CURSOR_CONVERSATION_ID` (Cursor),
  `CLAUDE_CODE_SESSION_ID` (Claude Code), `GROK_SESSION_ID` (Grok),
  `ANTIGRAVITY_CONVERSATION_ID` (Antigravity). Do not use recency when an ID is absent.
- Verify the returned session ID on every result, including "Up to date"; exit 0
  alone is insufficient. On missing/mismatched identity, preserve existing exports,
  stop this path, inspect only the intended session metadata, and report the failure.
  Never use `--mode replace` to repair identity.
- Add `--callsign "<your callsign>"` for your own main session if assigned. A callsign
  affects labeling only. Fresh-context child exports use their own opening assignment.
  Full-history child exports preserve and label inherited context; they use neutral
  `Codex_Sub` labeling when the child's assignment cannot be separated from copied history.
- `--mode append` re-parses and re-renders the whole transcript with shrink/fidelity
  guards. It is not literal line appending; unchanged content is a no-op. Preserve
  guard warnings verbatim, protected originals, and any companion's provenance.
- For children, require xexport **0.2.2+** on Codex. Parent-driven export is:
  `xexport subagents --source <claude|codex|cursor|grok|antigravity> --session-id "<exact parent id>" --format html --mode append --out "C:\Users\Roy Harden\OneDrive\PJ-OD\Bolt.New\judge-calibration-lab\.chatexports"`.
  Codex discovery includes direct children only; run again for each child with
  children of its own. Verify each returned ID against the explicitly linked child.
- Native Codex children may self-export when runtime `CODEX_THREAD_ID` matches
  metadata `payload.id` and the rollout filename. Metadata `session_id` and runtime
  `CODEX_SESSION_ID` can identify the parent. If the runtime ID is inherited/missing,
  have the parent use the verified exact child thread ID. Before 0.2.2, even an exact
  child ID is unsafe: report the unsupported path instead of attempting the write.
- Claude/Cursor children without a verified independent identity rely on their
  parent/hook; do not run `current` with an inherited parent ID and a child's callsign.
- Preserve parent/child last-success times, pending failures, and next freshness
  checkpoint in existing task status/handoff notes across compaction. Update success
  only after verification; report stale/failed children on status requests. This is
  execution policy, not authorization to install a watcher or scheduled automation.
- A receipt path you quote to another agent is a location, not permission to read it:
  transcripts hold the user's prompts and tool output.
- Exports are folders under `.chatexports\html\`. To read one, yours or another
  agent's, follow the `xexport-read` skill: page map in `index.html` first, then the
  `page-NNN.html` files, each sized for one read. Add `--format both` to also keep a
  single-file Markdown copy.
